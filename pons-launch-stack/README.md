# pons-launch-stack

> **⚠️ تغییر شکسته‌نده در این نسخه:** مسیر مشتق‌سازی ولت‌های کارگر به استاندارد BIP44 `m/44'/60'/0'/0/i` اصلاح شد (قبلاً اشتباهاً `m/44'/60'/0'/0/0/i` بود). با همان نمونیک، **آدرس‌های کارگر این نسخه با نسخه‌های قدیمی فرق دارد** — برای ادامه‌ی عملیات روی لانچ‌های قبلی: `--legacy-hd` در `fund/exit/sell` (مسیر قدیمی، فقط بازیابی) یا آدرس‌های قدیمی را از `launches/launch_*.json` بخوان و با `--recipients` ادامه بده.
> **تست آفلاین:** `npm test` (۶۹ تست بدون شبکه: بردارهای مرجع BIP44 + legacy، نردبان فروش، تخصیص BigInt، لاک مالکیت‌دار، فرمول سود، ژورنال اتمیک، ABI).

> **دومین ممیزیِ پاس خواست — اصلاحات مهم این نسخه:**
> ۱. **run-lock مالکیت‌دار اتمیک:** ساخت با `wx` + توکن مالک؛ اجرای دوم (حتی خطادار) دیگر لاک دیگری را پاک نمی‌کند؛ TOCTOU برطرف شد.
> ۲. **فرمول سود exit تصحیح شد:** بازده کل = (عایدی فروش‌های قبلی + ارزش خالص فعلی) نسبت به کل خرید — دیگر فروش جزئی، تریگر زودهنگام نمی‌سازد.
> ۳. **ژورنال با resume واقعی:** نام فایل تعیین‌شده بر اساس کرو/توکن، وریفای رسیدِ هر تراکنش در اجرای دوباره، بازیابی تراکنش‌های «در تعلیق»، نوشتن اتمیک + بکاپ `.bak` — هیچ خرید ماین‌شده‌ای دوباره انجام نمی‌شود.
> ۴. **تخصیص دقیق BigInt** (`splitWeiRandom`): جمع دقیقاً = total و هر سهم ≥ حداقل؛ اگر نشود ⇒ لغو با پیام (به‌جای سهم‌های زیرحداقل).
> ۵. **هیچ minOut=0 خاموشی نیست:** بدون قیمت مرجع، خرید/فروش لغو می‌شود مگر با `--min-out 0` یا `--allow-zero-minout` صریح.
> ۶. **قیمت anchor = آخرین معامله‌ی واقعی** (به‌جای میانه) و **به‌روزرسانی هر پله**؛ محاسبه‌ی minOut با ریاضی BigInt/Q64.
> ۷. **پنیک ناقص دیگر رصد را متوقف نمی‌کند:** ولت‌های باقی‌مانده در چرخه‌های بعد دوباره پنیک می‌شوند؛ پس از N تلاش با کد خروج ۲ و لیست آدرس‌ها متوقف می‌شود.
> ۸. **امضاکننده‌های تکراری (کلید یکسان) یونیک می‌شوند** — تصادم nonce رفع شد؛ `--pct-of-balance` فقط عدد صحیح؛ خطای هر پله ⇒ `exit 1`.
> ۹. **sell:** `--mode farm` (۱۰ پله‌ی ۱۰٪، round-robin، تأخیر ~۱ثانیه)، `--order rr`، `--ur-data-steps` (بلوب جدا برای هر پله — بلوب‌ها درون‌شان amountIn انکودشده دارند)، `--ur-command` (۰x10=V4 در استاندارد UR) و آماده‌سازی کامل Permit2 با `--permit2`.

> **محدوده‌ی صادقانه — چیزهایی که این بسته «عمداً» نیست:**
> - **سازنده‌ی WSS «Creator Watcher» نیست:** تشخیص خودکار لانچِ کریتور هدف از روی Factory event با `eth_subscribe` در این بسته نیست. جریان طراحی‌شده: تو خود `launch.js` را می‌زنی (یا با ربات بیرونیت ترکیبش می‌کنی) و `batch_buy` فوراً بعدش. اگر Watcher می‌خواهی، ماژول جدا با الزامات زیر لازم است و باید جدا تصمیم گرفته شود: `CREATOR_ADDRESS`، استقرار WSS قابل‌اعتماد، `TARGET_SECONDS`/`MAX_LAUNCH_AGE_SECONDS`.
> - **۲۸ خرید در ۲–۱۰ ثانیه با این معماری ممکن نیست (به انتخاب طراحی):** `batch_buy` یک payer است و قبل از هر ارسال شبیه‌سازی + چک گارد می‌آید → هر خرید ≈ ۰٫۵–۲ثانیه ⇒ مجموعاً ~۱۵–۶۰ ثانیه. موازی‌سازی واقعی نیازمند ۲۸ امضاکننده‌ی شارژشده‌ی مستقل + nonce جدا + broadcast هم‌زمان است (الگوی متفاوت مالی) — اگر خواستی به‌عنوان فیچر جدا تعریف کن.
> - **کال‌دیتای خودکار V4 ساخته نمی‌شود:** دیتای `execute` مسیر V4 به poolKey/هوک/پلنرِ deployment پونز وابسته است و بدون وریفای آنچین قابل‌حدس نیست؛ پس `sell.js --ur-data*` دیتا را از تو می‌گیرد و فقط Permit2/فرمان/شبیه‌سازی را مدیریت می‌کند.

> **بازسازی‌شده پس از سومین وایپ سندباکس (۲۰۲۶-۰۹-۲۱):** کد «دقیقاً» همان وضعیت تأییدشده‌ی دور چهارم بازبینی است (گزارش‌های تحقیق هم از یادداشت‌های تأییدشده بازسازی شده‌اند).

تولکیت عملیات‌گری روی قراردادهای **Pons V2** در **Robinhood Chain (chainId 4663)** — بازسازی دقیق الگوی فارم کشف‌شده از روی شواهد آنچین (شش لانچ موج دوم). تمام فراخوانی‌ها فقط روی کانترکت‌های **سورس‌دار و وریفای‌شده** (پونز/یونیسواپ) انجام می‌شود؛ کانترکت‌های فارم فقط «مرجع مطالعاتی»‌اند و هرگز صدا زده نمی‌شوند.

## مرحله‌ها (پایپلاین)

```
fund (فقط گس ≈ 0.06)  →  launch (یک تراکنش: لانچ+خرید اول+exemptions)
  →  batch_buy --launch-file (اول --dry-run)  →  claim --watch
  →  exit.js (خروج هدف‌دار خودکار)  |  sell (پله‌ای دستی)  →  sweep
```

## ۱) خزانه و ولت‌ها (`src/fund.js`)

```bash
node src/fund.js genmnemonic          # نمونیک جدید برای ولت‌های کارگر
node src/fund.js wallets --n 28       # نمایش آدرس‌های کارگر (m/44'/60'/0'/0/i)
node src/fund.js fund --total 0.06    # شارژ فقط-گس ۲۸ ولت (خرید باندل کار batch_buy/payer است)
node src/fund.js balance              # مانده‌خوانی
# ژورنال شارژ ولت‌ها در launches/wallets/fund_journal.json — ولتِ قبلاً شارژشده دوباره‌سوخت نمی‌شود
# (--force برای شارژ مجدد اجباری)
node src/fund.js sweep                # پس‌گیری به TREASURY_ADDRESS (نگه‌داشت ۰٫۰۰۰۰۵ رزرو؛ TREASURY ولیدیت می‌شود)
```

## ۲) لانچ (`src/launch.js`)

```bash
node src/inspect.js                                 # اول: فی/کانفیگ‌های فکتوری را بخوان
node src/launch.js --name "My Token" --symbol MYT --quote 0.003 --exemptions 28
```

- یک تراکنش اتمیک روی `LaunchAndBuy` (`0xe33e9e47…`): لانچ + خرید اول + ثبت `snipeTaxExemptions` (۲۸ ولت کارگر — **از ایندکس `WORKER_START`**).
- فی لانچ **از خود فکتوری آنچین** خوانده می‌شود (`launchFee()`) با fallback ‍‍`LAUNCH_FEE_ETH`.
- `creatorFeeRecipient` پیش‌فرض = **ولت کلیمر جدا** (الگوی موج دوم؛ اگر با کلیمر فرق کند هشدار می‌دهد).
- رکورد کامل در `launches/launch_*.json` ذخیره می‌شود: `token/curve/txHash/exemptions/workerStart` — **حتی اگر استخراج ایونت ناقص شود، فایل ساخته می‌شود.**
- `--dry factory` مسیر آزمایشی «لانچ فکتوری خالص بدون خرید اول» (الگوی روش B فارم).

## ۳) بچ‌بای «یک‌جا بخر، پخش کن» (`src/batch_buy.js`)

```bash
node src/batch_buy.js --curve 0xCURVE --token 0xTOKEN --total 3.0 --workers 28
node src/batch_buy.js --curve 0xCURVE --token 0xTOKEN --total 1.2 --recipients 0xA,0xB,0xC
# روش توصیه‌شده (بدون تایپوی آدرس — همه‌چیز از رکورد لانچ):
node src/batch_buy.js --launch-file launches/launch_XXX.json --total 3.0 --workers 28 \
  --launch-tx 0x... --external-abort-eth 0.6 --panic-sell
```

- یک ولت **payer** همه‌ی خریدها را می‌پردازد (`buy(quoteIn, minOut, recipient)` روی کرو — امضای وریفای‌شده)؛ توکن مستقیم در کیف ولت‌های معاف می‌نشیند.
- **سپرهای پولی:** ولیدیشن آدرس‌ها · چک موجودی payer قبل از شروع · **شبیه‌سازی `eth_call` قبل از هر ارسال** (ریورت ⇒ ETH از دست نمی‌رود) · نرمال‌سازی سهام تا جمع دقیقاً ≤ total · رزرو گس پویا (`gasPrice × 150k × n`) · gasPrice در هر خرید تازه می‌شود.
- **رکورد و لاک:** ژورنال اتمیکِ **resume/idempotent** در `launches/batchbuy_<curve>_<token>.json` — اجرای دوباره‌ی همین دستور خودکار ادامه می‌دهد: رسید هر تراکنش وریفای می‌شود، خریدهای ماین‌شده دوباره انجام نمی‌شوند و تراکنش‌های «broadcast ولی بی‌رسید» پیگرد می‌شوند (`--fresh`=ژورنال تازه، `--journal`=مسیر دلخواه). + فایل لاک مالکیت‌دار `launches/batch_buy.lock` (`--force` برای لاک مالکِ مرده).
- **گارد خرید خارجی:** اسکن `CurveBuy` با کرسر افزایشی (هر رویداد یک‌بار پردازش می‌شود، حالت cumulative)؛ هر خرید به گیرنده‌ی غیرخودی ≥ `--min-ext-tx` شمرده می‌شود. رد آستانه (`--external-abort-eth`، پیشنهاد ۱۵–۳۰٪ total) ⇒ **توقف فوری باندل** + (با `--panic-sell`) **خروج موازی کامل کریتور + همه‌ی باندل‌ها**. خطای RPC پیاپی (۳ بار) ⇒ گارد **fail-closed** توقف امن می‌کند.
- **قیمت/لغزش:** minOut هر خرید از قیمت بازار (فیل‌های اخیر/مارک) با `SLIPPAGE_BPS` تخمین زده می‌شود؛ override با `--min-out`. گارد را با `--no-guard` خاموش کن (توصیه نمی‌شود).
- **توقف خودکار در گرجوئیشن** (پیش‌فرض روشن؛ `--ignore-graduation` خاموش می‌کند): ابتدا توابع view رایج، وگرنه heuristic افت ~۹۰٪ رزرو کرو.
- حالت دیده‌بان: `--watch-only --external-abort-eth X --watch-minutes 30`. در `--dry-run` همه‌چیز شبیه‌سازی می‌شود و شکست شبیه‌سازی ⇒ `exit code 2` (با این نکته که dry-run روی حالت فعلی زنجیره است نه حالت پس از خرید ۱..i‌ام).
- نمایش توکن با **decimals واقعی** توکن خوانده‌شده آنچین.

## ۴) کلیم فی (`src/claim.js`)

```bash
node src/claim.js --watch            # هر ۶۰ ثانیه پول می‌کند و claim می‌زند (اورلود claim() صریح انتخاب شده)
node src/claim.js --watch --sweep    # بعد از هر کلیم موفق، به خزانه خالی می‌کند
node src/claim.js --all              # مانیتورینگ: مانده‌ی قابل کلیم مستر+کارگرها هم نمایش داده می‌شود
```

## ۵) خروج خودکار هدف‌دار (`src/exit.js`)

```bash
node src/exit.js --curve 0xC --token 0xT --launch-tx 0x<هش لانچ>
node src/exit.js --curve 0xC --token 0xT --launch-tx 0x... --min-profit-pct 125 --fee-bps 300
node src/exit.js ... --self-extra 0xW1,0xW2   # ولت‌های خودیِ خارج از امضاکنندگان: فقط مانیتورینگ، وارد سرمایه نمی‌شوند
node src/exit.js ... --legacy-hd             # بازیابی: ولت‌های مسیر قدیمی اشتباه (لانچ‌های قبل از اصلاح BIP44)
```

فرمول سود (اصلاح‌شده): **بازده کل = (عایدی فروش‌های قبلی + ارزش خالص فعلی) ÷ کل خرید** — فروش جزئی دیگر تریگر زودهنگام نمی‌سازد. پنیک ناقص رصد را متوقف نمی‌کند؛ پس از `--panic-max-attempts` (پیش‌فرض ۸) با کد ۲ و لیست ولت‌های باقی‌مانده متوقف می‌شود. امضاکننده‌ها یونیک می‌شوند (کلید تکراری = تصادم nonce).

مدل (همه‌چیز از آنچین، بدون هاردکد سرمایه): سرمایه = جمع `quoteIn` خریدهای خودی · فلوت = خالص توکن خارج از کرو · قیمت = میانه‌ی آخرین K معامله · ایمپکت خطی `مارک × (۱ − Q/2F)` · خالص = مارک × ایمپکت × (۱ − فی).
**تریگر پیش‌فرض: سود خالص ≥ ۱۰۰٪ «بعد» از ایمپکت/فی ⇒ خروج موازی کامل (همان موتور پنیک).** هر چرخه «ضریب مارک لازم» را هم گزارش می‌کند و پس از خروج، پرشدنی واقعی با مدل مقایسه و هشدار می‌دهد.

## ۶) فروش پله‌ای دستی (`src/sell.js`)

```bash
node src/sell.js --token 0xT --curve 0xC --mode farm --workers 28        # ۱۰ پله‌ی ۱۰٪، round-robin، ~۱ثانیه فاصله
node src/sell.js --token 0xT --curve 0xC --mode gradual --workers 28
node src/sell.js --token 0xT --order rr --mode micro --workers 28       # round-robin روی همه‌ی مُدها
node src/sell.js --token 0xT --ur-data-steps "0xA,0xB,..." --ur-command 0x10 --permit2
```

- نماها: `gradual` (۱۶×۵+۲۰) / `aggressive` (۴۵+۴۵+۱۰) / `micro` / **`farm`** (۱۰×۱۰٪ + rr + ۱ثانیه — الگوی سرعت).
- **قیمت و minOut هر پله تازه می‌شود** (anchor = آخرین معامله‌ی واقعی)؛ بدون قیمت ⇒ لغو مگر `--min-out 0`.
- مسیر UR: `amountIn` داخل بلوب انکودشده است ⇒ **برای هر واحد پله بلوب جدا (--ur-data-steps)**؛ `--ur-command` انتخابی (۰x10 = V4 در استاندارد UR — deployment پونز را روی Blockscout چک کن)؛ Permit2 با `--permit2`. شبیه‌سازی قبل از هر ارسال؛ شکست هر پله ⇒ `exit 1`.

## ۷) جمع‌آوری پایانی

```bash
node src/fund.js sweep
```

## ✅ چک‌لیست پرواز امن (قبل از پول واقعی)

1. **`--dry-run` اول:** قبل از هر بچ‌بای واقعی، یک شبیه‌سازی کامل بدون ارسال اجرا کن — خروجی باید ۲۸/۲۸ OK باشد:
   ```bash
   node src/batch_buy.js --launch-file launches/launch_XXX.json --workers 28 --total 3.0 --dry-run
   ```
2. **`--launch-file`** را همیشه بده: کرو/توکن/launch-tx از رکورد لانچ تزریق می‌شود و recipientها با exemptionsِ لانچ سخت‌گیرانه چک می‌شوند — بزرگ‌ترین ریسکِ «تایپوی آدرس» صفر می‌شود.
3. **پول کم برای اولین اجرای واقعی:** اولین اجرا با `total` کوچک (مثلاً ۰٫۰۵) انجام شود تا ریختار زنجیره واقعی دیده شود.
4. **شارژ payer قبل از اجرا:** اسکریپت خودش چک و لغو می‌کند اگر کم باشد — ولی بهتر است قبل از لانچ شارژ شده باشد.
5. **منطق پیام‌های شکست:** شبیه‌سازی `eth_call` قبل از هر buy/sell اجرا می‌شود؛ هر تراکنشی که ریورت می‌کند قبل از ارسال گرفته می‌شود → ETH از دست نمی‌رود (فقط آن ولت از چرخه بیرون می‌ماند و در فایل ثبت می‌شود).
6. **هر اجرا رکورد می‌سازد:** حتی در توقف ناقص، نقشه‌ی ولت‌های خریداری‌شده در `launches/*.json` برای بازیابی هست — قبل از هر اقدام تکمیلی، این فایل را چک کن.
7. **گارد خارجی + exit.js** همیشه در پنجره‌ی آغازین بازار بالا باشند (فاز دفاع ورود و خروج هدف‌دار).
8. **قانون آفست کارگرها:** مجموعه‌ی ولت‌های کارگر در همه‌ی مراحل باید یکی باشد (`--worker-start` یا `WORKER_START` در env؛ پیش‌فرض ۰). آفست در رکورد لانچ ذخیره می‌شود و `batch_buy --launch-file` همان را خودکار اعمال می‌کند؛ برای مراحل دیگر (`fund/exit/sell`) همان فلگ یا env را بدهید. ناهماهنگی آفست = ولت‌های اشتباه.

## محدودیت‌های صادقانه

- مدل ایمپکت **خطی و تقریبی** است — برای کروی با ساپلای بزرگ خوش‌بینانه و با ساپلای کوچک بدبینانه می‌شود؛ با فیل‌های واقعی کالیبره کنید (`--fee-bps` محافظه‌کارتر یا آستانه بالاتر).
- هر خروج فوری **مسابقه‌ی بلاکی** است؛ موتور پنیک فاصله را به حداقل می‌رساند (nonce صف‌دار + fallback)، حذفش نمی‌کند. هیچ ترتیب اجرایی در بلاک تضمینی نیست.
- گارد خارجی به `getLogs` عمومی وابسته است — RPC اختصاصی در `.env` بگذارید.
- recipient اشتباه **غیرقابل‌بازگشت** است (به‌همان دلیل چک سخت launch-file).

کلیدها هیچ‌وقت از ماشین شما خارج نمی‌شوند؛ فقط امضای محلی + RPC.
