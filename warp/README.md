# عیب‌یابی WARP — چرا IP کلادفلر آمد، چرا آلمان ماند، چرا کند شد

## خلاصه در یک نگاه

سه مشکل جدا با هم قاطی شده. هر کدام علت و راه‌حل خودش را دارد:

| مشکل | علت | راه‌حل |
|---|---|---|
| IP کلادفلر آمد | **طبیعی است** — WARP همیشه خروجی‌اش IP کلادفلر است | قابل تغییر نیست |
| لوکیشن همان آلمان ماند | anycast: WARP نزدیک‌ترین گره را می‌گیرد. سرور آلمانی → گره فرانکفورت | `warp-scan.py --scan` |
| سرعت افت کرد | MTU اشتباه + اولویت پایین پلن رایگان + رمزنگاری دوگانه | MTU = ۱۲۸۰ + بهینه‌سازی |

---

## ۱. «IP کلادفلر آمد» — این باگ نیست

WARP شبکه‌ی کلادفلر است. هر ترافیکی که از آن رد شود، **از IP کلادفلر** بیرون می‌آید. این طراحی WARP است، نه خرابی.

### ولی این یک مشکل واقعی است

| سرویس | مشکل با IP کلادفلر |
|---|---|
| بانک‌ها و درگاه‌های پرداخت | بسیاری IP کلادفلر را مسدود می‌کنند |
| سرویس‌های استریم (نتفلیکس، دیزنی) | اکثراً بلاک |
| سایت‌های ایرانی | بعضی‌ها |
| سایت‌هایی با «Cloudflare ban» | به‌خاطر سوءاستفاده، بلاک شده‌اند |
| کپچا | گوگل کپچای سخت‌تر می‌دهد |

**پس اگر هدف شما باز کردن سایت‌های خاص است، WARP ممکن است اصلاً به کار نیاید** — نه به‌خاطر فیلترینگ، بلکه چون آن سایت خودش کلادفلر را بلاک کرده.

> ⚠️ و یک نکته‌ی مهم: کلادفلر رسماً اعلام کرده **WARP برای تغییر لوکیشن ساخته نشده** و برای این کار طراحی نشده. کاری که ما می‌کنیم (اسکن endpoint) یک ترفند است که کار می‌کند ولی خارج از طراحی رسمی آن است و ممکن است هر زمان عوض شود.

## ۲. «لوکیشن همان آلمان ماند» — این حل می‌شود

### چرا این اتفاق افتاد

WARP از **anycast** استفاده می‌کند:
```
سرور شما در آلمان
      │
      ▼  «نزدیک‌ترین گره کجاست؟»
   ┌──────┐
   │ FRA  │  ← فرانکفورت (گره آلمان)
   └──────┘
      │
      ▼
  سایت مقصد: «این بازدیدکننده آلمانی است»
```

مسیر خروجی شما (`wg0` یا هر اینترفیس دیگری که ساختیم) از همان منطقه بیرون می‌آید، پس سایت‌ها آلمان می‌بینند. حتی اگر endpoint را به کشور دیگری بدهید، ممکن است همچنان آلمان گزارش شود.

### راه‌حل: اسکن endpoint

خبر خوب: کلادفلر هزاران آدرس endpoint دارد و **هر کدام به گره متفاوتی می‌رود**. با انتخاب درست، می‌توانید کشور خروجی را عوض کنید.

ابزاری که برای همین ساختم:

```bash
# ۱) اول تشخیص بده مشکل کجاست
sudo python3 warp-scan.py --iface wgcf --check
```

خروجی نمونه:
```
[+] اینترفیس wgcf موجود است
    endpoint فعلی: 162.159.192.1:2408
[!] MTU = 1420  ← زیاد است، کندی می‌آورد
       پیشنهاد: MTU = 1280

--- trace بدون WARP (مستقیم) ---
    ip=5.6.7.8  colo=FRA  loc=DE

--- trace از داخل WARP ---
    ip=188.114.98.58  colo=FRA  loc=DE
    warp=on  gateway=off

[!] کشور خروجی با حالت مستقیم یکی است (DE)     ← 🎯 مشکل پیدا شد
       یعنی endpoint فعلی به گره‌ای می‌رود که کاربر را در همان کشور نشان می‌دهد
```

```bash
# ۲) اسکن کن، فقط کشورهای مورد نظرت
sudo python3 warp-scan.py --iface wgcf --scan --want DE,NL,US,FR,GB
```

خروجی نمونه:
```
  loc   colo   endpoint                      tcp      ip خروجی
  --------------------------------------------------------------
  DE    FRA    188.114.98.58:2408          12.4ms    188.114.98.58
  DE    FRA    162.159.192.1:500           19.1ms    162.159.192.1
  NL    AMS    188.114.99.10:2408          24.7ms    188.114.99.10
  US    IAD    162.159.193.5:1701          98.3ms    162.159.193.5
  GB    LHR    162.159.204.7:2408          31.2ms    162.159.204.7

[+] بهترین endpoint هر کشور ذخیره شد: warp-best.txt
```

### تفاوت مهم: `loc` با `colo`

| ستون | معنا |
|---|---|
| **`colo`** | گره‌ای که تونل از آن رد می‌شود (مثلاً FRA = فرانکفورت) |
| **`loc`** | 🎯 **کشوری که سایت‌ها شما را در آن می‌بینند** |

این دو **متفاوتند**! یک تونل می‌تواند از فرانکفورت رد شود ولی شما را روسی نشان دهد. پس همیشه `loc` را ببینید، نه `colo`.

### اعمال کردن endpoint انتخاب‌شده

```bash
# در kانفیگ wgcf، خط Endpoint را عوض کنید:
sudo nano /etc/wireguard/wgcf.conf
# Endpoint = 188.114.99.10:2408

sudo wg-quick down wgcf && sudo wg-quick up wgcf

# یا بدون قطع شدن:
sudo wg set wgcf peer <PUBLIC_KEY> endpoint 188.114.99.10:2408
```

### ابزار جایگزین که خوب کار می‌کند

اگر دنبال اسکنر کامل‌تری هستید: **[warpscout](https://github.com/vernette/warpscout)** — endpoint ها را اسکن می‌کند، گره و کشور خروجی را نشان می‌دهد، و کانفیگ آماده می‌سازد:

```bash
warpscout scan -p awg -P --country DE,NL,US --best
warpscout scan -p wg -P --exclude-node DME
```

## ۳. «سرعت افت می‌کند» — سه علت دارد

### علت اول (و بزرگ‌ترین): MTU اشتباه ⚡

این معمولاً **۸۰٪ مشکل سرعت** است. مقدار پیش‌فرض wgcf برابر ۱۴۲۰ است و برای WARP اشتباه است.

**چرا:** بسته‌های بزرگ‌تر از مسیر عبور نمی‌کنند و به تکه‌تکه شدن می‌افتند → کندی و گیر کردن.

```bash
# MTU را به ۱۲۸۰ برسانید
sudo nano /etc/wireguard/wgcf.conf
# MTU = 1280   ← این خط را اضافه یا اصلاح کنید

sudo wg-quick down wgcf && sudo wg-quick up wgcf
```

**سرعت واقعی این تفاوت:** کاربران گزارش کرده‌اند که با تنظیم MTU روی ۱۳۳۰، سرعت از **۴۰-۶۰ Mbps به ۲۸۵ Mbps** رسیده. یعنی می‌تواند ۵ برابر شود.

اگر ۱۲۸۰ هم خوب نبود، این مقادیر را هم امتحان کنید: `1360`, `1330`, `1240`, `1200`

**ابزار پیدا کردن MTU بهینه:**
```bash
python3 -c "
import subprocess
for mtu in [1420,1400,1380,1360,1340,1320,1300,1280,1260,1240,1200]:
    size = mtu - 28
    r = subprocess.run(['ping','-c','1','-W','2','-M','do','-s',str(size),'1.1.1.1'],capture_output=True)
    print(f'  MTU {mtu}:', '✅' if r.returncode==0 else '❌')
"
```

### علت دوم: اولویت پایین پلن رایگان

WARP رایگان در شبکه کلادفلر **اولویت پایینی** دارد. پلن WARP+ مسیریابی هوشمند (Smart Routing) دارد که در شبکه‌های پرترافیک بهتر عمل می‌کند و طبق تست‌های ۲۰۲۵-۲۰۲۶ تأخیر را ۱۰-۳۰٪ و لرزش را ۲۰-۶۰٪ کم می‌کند.

این قابل دور زدن نیست — هزینه‌ی رایگان بودن است.

### علت سوم: رمزنگاری دوگانه

مسیر شما:
```
کاربر ──VLESS+REALITY──> سرور آلمان ──WireGuard──> WARP ──> سایت
         ↑ رمزنگاری ۱                    ↑ رمزنگاری ۲
```
دو لایه رمزنگاری + یک هاپ اضافه = تأخیر بیشتر و CPU بیشتر.

**راه‌های کاهش:**
1. سرور خروجی را به گره WARP نزدیک کنید (سرور آلمانی → گره آلمان، نه آمریکا)
2. CPU سرور را چک کنید — WARP زیاده‌روی CPU دارد:
   ```bash
   htop   # اگر CPU ۱۰۰٪ است، این گلوگاه شماست
   ```
3. BBR را فعال کنید:
   ```bash
   cat | sudo tee /etc/sysctl.d/99-bbr.conf <<'EOF'
   net.core.default_qdisc = fq
   net.ipv4.tcp_congestion_control = bbr
   net.ipv4.tcp_fastopen = 3
   EOF
   sudo sysctl --system
   ```
4. `PersistentKeepalive = 25` را در کانفیگ داشته باشید (سرعت اتصال مجدد)

## 🎯 وارپ را کجا بگذاریم؟ (مهم‌ترین نکته‌ی معماری)

شما وارپ را **روی سرور خارجی** گذاشتید. ولی بسته به هدف، جای درست متفاوت است:

### حالت الف: وارپ روی سرور خارجی (کاری که کردید)
```
کاربر → سرور ایران → سرور آلمان → WARP → سایت
```
- ✅ می‌تواند کشور خروجی را عوض کند (با اسکن endpoint)
- ❌ IP خروجی کلادفلر است → سایت‌های حساس بلاک می‌کنند
- ❌ دو هاپ اضافه → کندتر
- ❌ سرعت کاربر به سرعت سرور آلمان محدود است

### حالت ب: وارپ فقط به‌عنوان یکی از خروجی‌ها
```
                        ┌─ wg0 (آلمان، مستقیم)     ← برای سایت‌های حساس
کاربر → سرور ایران → سرور آلمان ──┼─ wg1 (هلند، مستقیم)
                        └─ wg-warp (کلادفلر)        ← فقط برای دور زدن فیلترینگ ساده
```
**این بهتر است.** در `wg-multipath.py` وارپ را به‌عنوان **یکی از** اینترفیس‌ها اضافه کنید، نه تنها راه. بعد در Xray:

```json
{ "tag": "warp-out", "protocol": "freedom",
  "streamSettings": { "sockopt": { "mark": 1010 } } }
```

و در routing برای سایت‌های حساس از خروجی مستقیم استفاده کنید:
```json
{ "type": "field", "domain": ["domain:bank.com", "geosite:netflix"],
  "outboundTag": "wg-de" },
{ "type": "field", "outboundTag": "warp-out" }
```

### حالت ج: وارپ روی دستگاه کاربر (نه سرور)
اگر کاربر خودش WARP داشته باشد، ساده‌ترین و سریع‌ترین ترکیب است — WARP + کانفیگ شما به‌عنوان لایه دوم.

## 🔴 محدودیت‌های WARP که باید بدانید

| محدودیت | توضیح |
|---|---|
| IP کلادفلر | همیشه. سایت‌های زیادی آن را بلاک می‌کنند |
| وابسته به anycast | انتخاب کشور **تضمینی نیست**، ممکن است فردا عوض شود |
| طراحی رسمی | کلادفلر می‌گوید: «WARP برای تغییر لوکیشن ساخته نشده» |
| پلن رایگان | اولویت پایین در شبکه، بدون Smart Routing |
| شرط استفاده | WARP برای دستگاه‌های شخصی طراحی شده. استفاده‌ی آن به‌عنوان دروازه‌ی خروجی برای چندین کاربر، خارج از کاربرد مورد نظر آن است |
| قطع سراسری | چند بار در سال، کل شبکه WARP برای ایران قطع می‌شود |

**اگر یکی از این‌ها برایتان مسئله‌ساز است، WARP ابزار اشتباهی است.**

## 📋 چک‌لیست سریع برای مشکل فعلی شما

```bash
# ۱) MTU را درست کن — احتمالاً بیشترین تأثیر را دارد
sudo nano /etc/wireguard/wgcf.conf     # MTU = 1280
sudo wg-quick down wgcf && sudo wg-quick up wgcf

# ۲) ببین در چه وضعیتی هستی
sudo python3 warp-scan.py --iface wgcf --check

# ۳) کشور خروجی را عوض کن
sudo python3 warp-scan.py --iface wgcf --scan --want DE,NL,US

# ۴) BBR را فعال کن
cat | sudo tee /etc/sysctl.d/99-bbr.conf <<'EOF'
net.core.default_qdisc = fq
net.ipv4.tcp_congestion_control = bbr
EOF
sudo sysctl --system

# ۵) سرعت را اندازه بگیر
curl -o /dev/null -w "سرعت: %{speed_download} بایت/ثانیه\n" https://speed.cloudflare.com/__down?bytes=50000000
```

## عیب‌یابی

| مشکل | علت | راه‌حل |
|---|---|---|
| `warp=off` در trace | ترافیک از تونل نمی‌رود | `ip route` را چک کنید؛ یا از `--interface` استفاده کنید |
| اسکن هیچ نتیجه‌ای نداد | اینترفیس بالا نیست | `sudo wg-quick up wgcf` بعد دوباره اسکن |
| همه endpoint ها یک کشور می‌دهند | آن گره در آن منطقه مستقر است | `--sample 30` برای اسکن بیشتر، یا `--full` |
| سرعت خوب است ولی سایت باز نمی‌شود | سایت IP کلادفلر را بلاک کرده | راهی نیست — از VPS استفاده کنید |
| اتصال مرتب قطع می‌شود | MTU | ۱۲۴۰ را امتحان کنید |
| پس از چند ساعت کند می‌شود | محدودیت پلن رایگان | endpoint را عوض کنید یا WARP+ |
| `wg set` خطا می‌دهد | کلید peer اشتباه | `sudo wg show wgcf peers` |
